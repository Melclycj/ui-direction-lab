## ⚡ Compute tier (perf-cost) — a mandatory column this pool introduced, being rolled out to every effect pool

> **Why (the user's insight, 2026-07-08)**: the sites with ever flashier effects are also getting
> ever more sluggish; a user on a weak machine gets no fluency, and **a stuttering hero is a hero
> that failed its job**. So every effect admitted must carry a compute tier plus a weak-machine
> fallback strategy.

| Tier | Definition | Weak-machine strategy |
|---|---|---|
| **light** | CSS/DOM transforms, GPU compositing layers, no heavy resident rAF | no fallback needed |
| **medium** | a single WebGL scene / resident rAF, small geometry (particles <5k), fine on integrated graphics | a reduced-motion still frame is enough |
| **heavy** | large particle counts / many lights / a post-processing chain / per-frame CPU simulation (boids, physics) | a fallback is **mandatory**: fewer particles / cut it on mobile / a still-frame stand-in |
| How it is calibrated | record an **initial tier (from experience)** on admission; calibrate it against a real CPU-throttled measurement when the piece is rebuilt or consumed, and write that back | — |

## 🏷 Mechanism tags + the consumption contract (pool architecture decision, ruled by the user 2026-07-08; **canonical at library level** — motion-pool and others point here)

> The decision: the registration layer stores "a demo + **a first-impression call (non-binding)**"
> (the user's first-glance sense of "what is this good for" is an index hint, not a usage
> restriction); **when the piece is rebuilt or its real code is read**, a five-layer dissection
> produces a "mechanism tag" written back onto **the same row** — and **only graduated entries are
> entitled to a tag** (tagging without having read the real code is guessing, and is forbidden). An
> agent recombining across carriers relies on the tag alone and is not bound by the first-impression
> call (mechanism ≠ carrier).

**The five-layer dissection** (the method for tagging): `driver` (scroll/pointer/load/click) ·
`mechanism` (the core visual trick) · `carrier` (the structural surface it fits; marking it
"irrelevant" means it crosses carriers) · `content` (image/text/3D/any) · `register` (temperament
affinity, a soft field). The compute tier has its own column and is not repeated.

**The consumption contract — four lines of defence when an agent draws candidates from graduated
entries**:
1. **A filter chain, not a ranking**: register match (the chassis's locked value × the tag's
   register; a borderline case is marked ⚠️ and still enters the candidate set rather than being
   hard-filtered) → carrier match → compute budget → driver conflict (taste §8: at most one main
   choreography per page, so if a scroll choreography already exists, only hover/load mechanisms may
   enter). **Every survivor becomes a different candidate variant**; there is no "pick one of them".
2. **No two pieces on the same mechanism in one batch** (an extension of the batch discipline of one
   axis at a time — two motion candidates on the same mechanism is a violation and gets redone).
3. **Write down the reason**: each candidate's readme states "why this mechanism suits this register
   and this content", traceable back to the brief or the chassis; not being able to write the reason
   is a red flag.
4. **Row order carries no priority**; **enumerate every filter survivor first**, then allocate them
   to candidates (this treats position bias).

The final choice belongs to a human (the batch goes to the user to pick); for a marquee or signature
moment, put the mechanism shortlist in front of the user.
