## ⚡ 算力档(perf-cost)——本池首创的强制列,逐步推广到所有效果类池

> **起因(用户 2026-07-08 洞察)**:效果越来越炫的站也越来越卡;弱机用户打不流畅,
> **hero 卡顿 = hero 失职**。所以每条效果入池必须标算力档 + 弱机 fallback 策略。

| 档 | 定义 | 弱机策略 |
|---|---|---|
| **轻** | CSS/DOM transform,GPU 合成层,无持续重 rAF | 无需 fallback |
| **中** | 单场景 WebGL / 持续 rAF,几何量小(粒子 <5k),集显 OK | reduced-motion 静帧即可 |
| **重** | 大粒子量 / 多灯 / 后期链 / CPU 逐帧仿真(boids/物理) | **必须**带降级:降粒子数 / 移动端裁剪 / 静帧替身 |
| 标定方式 | 入池时先记**初标(经验)**;复刻/消费时用 CPU throttle 实测校准并回写 | — |

## 🏷 机制标签 + 消费契约(池架构决议 2026-07-08 用户拍板;**库级 canonical**,motion-pool 等指此)

> 决议:入册层存「demo + **初见判(非绑定)**」(用户第一眼"适合做什么"=索引提示,不是使用限制);
> **复刻/读真码时**按五层解剖打「机制标签」回填**同一行**——**标签只有毕业条目配拥有**
> (没读过真码打标签=猜,禁止)。agent 跨载体重组只依据标签,不受初见判束缚(机制≠载体)。

**五层解剖**(打标签的方法):`驱动`(scroll/pointer/load/click)· `机制`(核心视觉戏法)·
`载体`(结构适配面;标"无关"=可跨载体)· `内容`(图/文/3D/任意)· `register`(气质亲和,软字段)。
算力档已单列,不重复。

**消费契约——agent 从毕业条目提候选时的四道防线**:
1. **过滤链,不是排序**:register 匹配(chassis 锁定值 × 标签 register;边界 case 标 ⚠️ 进候选,不硬滤)
   → 载体匹配 → 算力预算 → 驱动冲突(taste §8 一页至多一个主编排:已有 scroll 主编排则只准入
   hover/load 机制)。**幸存者全部进不同候选变体**,不存在"从中挑一个"。
2. **同批禁同机制**(batch"一批一轴"纪律的延伸——两个 motion 候选用同一机制=违规重做)。
3. **理由落笔**:每个候选的 readme 写"为什么这个机制配这个 register/内容",须可追溯到 brief/chassis;
   写不出理由=红旗。
4. **行序无优先级含义**;先**枚举全部过滤幸存者**再分配到候选(治 position bias)。

终选权在人(batch→用户挑);marquee/招牌时刻的机制 shortlist 建议给用户过目。

### 批次二 · 同机制族观察(2026-07-08 毕业批次,parent 跨组整合;只标注不合并行,合并与否留用户定夺)

1. **C-20 = C-21 同一仓库**:两条实为 `akella/PolygonTransitions` 的两个入口(Codrops 文章版 vs tympanus Development 版),demo 编号错位——同一套"三角网格几何拆分+逐三角错峰"骨架的 4+ 变体。**已于 2026-07-08 经用户批合并为一行 C-20/21**(两处初见判原话均保留)。

3. **C-03 ≈ C-10 同用 Bayer 有序抖动,载体两档**:C-03=16 万 InstancedMesh 3D 网格逐格抖动(重),C-10=全屏后处理 pass 查表(中)。同一视觉语言两档成本,选型时互为替代。

5. **C-31/C-33 同作者(ReGGae)同代码骨架非同机制**:工程骨架完全同构(可共享工程化改造),视觉手法一个是位移贴图 crossfade、一个是拖速波浪+RGB 分离,标签分开。
6. **跨条 recurring motif:"滚动/拖拽速度→sin 形变(±RGB 通道分离)"**——C-04/C-06/C-26/C-28/C-33 各自独立实现同一手法家族(速度值喂顶点 sin 位移或片元通道偏移)。消费契约"同批禁同机制"判重时按此 motif 算同族。
